# TahfeezAI — Design Direction

## Design objective

TahfeezAI should use excellent modern Quran applications, including QuranApp, as **UX and visual-quality references**, not as designs to reproduce.

Target approximately **50–60% familiarity in overall design language** while building a clearly independent TahfeezAI identity.

A QuranApp user should find the application intuitive quickly, but nobody should mistake TahfeezAI for QuranApp.

## Tahfeez character

Tahfeez should feel:

- modern;
- calm;
- elegant;
- premium without being flashy;
- spacious;
- Quran-focused;
- memorization-focused;
- typography-led;
- consistent across Android, iOS, tablet, and web.

Avoid:

- excessive ornament;
- heavy gold everywhere;
- mosque imagery on every screen;
- dense utility-app layouts;
- harsh pure-white expanses;
- excessive shadows;
- decorative Islamic patterns that reduce readability.

Islamic geometric motifs may appear subtly in branding or empty/decorative states, but content should remain visually quiet.

## Inspiration that may be retained

Use the reference application to learn from:

- Material 3 discipline;
- card-based organization;
- strong Quran access;
- readable settings grouping;
- bottom-sheet interaction for secondary actions;
- compact audio-player integration;
- reader controls that recede when reading;
- clear separation between Arabic Quran text and supporting content;
- good dark-mode behavior;
- offline-resource states;
- navigation concepts.

## Areas Tahfeez should deliberately change

Tahfeez should be:

- slightly more spacious;
- softer and more editorial;
- less visually dense;
- more rounded;
- stronger in typography;
- stronger in light mode;
- more responsive on tablet/web;
- more obviously centered on memorization as milestones progress.

Do not mirror the exact home layout if a better Tahfeez composition exists.

## Light mode is first-class

Light mode must be designed intentionally.

Suggested character, not mandatory exact values:

- warm off-white page background;
- clean light surfaces;
- deep emerald/teal primary;
- subtle green containers;
- warm restrained gold accent;
- dark neutral text;
- soft neutral outlines;
- minimal shadows.

Example starting palette for exploration:

- background: `#F7F8F4`
- surface: `#FFFFFF`
- primary: `#176B5B`
- primary accent: `#218A73`
- primary container: `#DCEFE8`
- text: `#18201D`
- secondary text: `#68736E`
- border: `#E4E8E5`
- muted gold: `#B79A5B`

These are Tahfeez exploration values, not values copied from a reference app. The design system milestone may adjust them for contrast and consistency.

## Dark mode

Dark mode should be designed independently, not generated by simply inverting light colors.

Desired character:

- deep green-charcoal background;
- layered dark surfaces;
- muted emerald highlights;
- comfortable off-white Quran-supporting UI text;
- low-glare reading environment.

Example exploration values:

- background: `#101513`
- surface: `#171D1A`
- elevated surface: `#1D2521`
- primary: `#68C6A8`
- primary container: `#203D34`
- text: `#ECF2EF`
- secondary text: `#AAB6B0`

## Reader themes

Application theme and Mushaf reading theme should be separable where technically sensible.

Possible reader appearances:

- Light
- Warm
- Sepia
- Dark
- Black

Quran correctness and font fidelity take priority over decorative styling.

## Shape and density

Prefer:

- cards around 16–20 logical pixels radius;
- low-contrast boundaries;
- restrained elevation;
- clear section spacing;
- touch-friendly controls;
- fewer cramped rows;
- generous but not wasteful whitespace.

Use a consistent spacing scale rather than arbitrary padding values.

## Typography

UI typography and Quran typography are separate systems.

### UI typography

Use a modern, highly legible family with excellent Arabic and Latin support.

Suggested hierarchy:

- display: 32–36
- page title: 26–30
- section title: 18–20
- card title: 16–18
- body: 14–16
- metadata: 12–13

Exact values should be implemented as semantic design tokens.

### Quran typography

Never render canonical Quran text using the generic application font.

Quran rendering should use the selected Quran script/font/rendering system.

## Home direction

Early milestones may remain inspired by successful Quran reading applications, but Tahfeez should increasingly prioritize:

- Continue Reading
- Today's Memorization
- Today's Revision
- Daily Ayah
- Recent Quran
- Memorization Progress
- Explore Quran

Before memorization exists, placeholders or reading-focused equivalents are acceptable.

## Primary navigation

At initial reader parity stages, a simple Quran-centered navigation hierarchy is acceptable.

Once memorization is production-ready, Tahfeez should expose four clear product areas:

- Home
- Quran
- Memorize
- Search

Do not blindly retain another application's navigation once Tahfeez's product needs differ.

## Quran reader

When reading begins, application chrome should visually recede.

Desired behavior:

- Quran content is the visual focus;
- controls appear when needed;
- top/bottom chrome can collapse;
- selected verse actions remain discoverable;
- audio state is visible but not dominant;
- Mushaf mode feels closer to reading a physical Mushaf than browsing a generic app screen.

## Memorization visual language

This is a major Tahfeez differentiator.

Design states for:

- visible text;
- hidden text;
- partially revealed text;
- current ayah;
- current word;
- listening state;
- correct recognition;
- skipped word;
- incorrect word;
- hesitation;
- self-correction;
- weak memory range;
- scheduled revision;
- completed session.

Do not change the Quran text itself to express states. Use overlays, backgrounds, underlines, markers, opacity, masks, or adjacent feedback.

## Motion

Motion should be subtle and meaningful:

- sheet transitions;
- selection feedback;
- page movement;
- memorization reveal;
- AI listening transitions;
- progress changes.

Avoid ornamental motion around Quran text.

## Responsive design

Do not stretch the phone layout across large screens.

Phone:
- compact navigation;
- single-page Mushaf;
- bottom sheets.

Tablet:
- navigation rail where useful;
- optional two-page Mushaf;
- side panels where space allows.

Desktop/Web:
- adaptive navigation;
- constrained reading width;
- optional side panel for tafsir/translation/notes;
- keyboard interactions.

## Conflict rule

If a reference specification and this document conflict on visual appearance:

**follow this document while preserving required functionality and workflow.**

When choosing between:
1. reproducing QuranApp more exactly; and
2. improving the experience consistently with TahfeezAI;

prefer option 2.

The intended result is:

> Clearly inspired by excellent modern Quran applications, including QuranApp, but recognizably and confidently TahfeezAI.
